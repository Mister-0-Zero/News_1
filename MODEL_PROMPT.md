Работай прямо в существующем GitHub-репозитории https://github.com/Mister-0-Zero/News_1 . Нужно заполнить и оформить подготовленный шаблон корпоративной новости для живой демонстрации создания материалов конкурса певцов с помощью ИИ.

1. Изучи AGENTS.md, README.md, index.html, styles.css, script.js и content.json. Проверь текущую ветку, git status и настройки GitHub Pages. Сохрани чужие незакоммиченные изменения. Используй этот репозиторий, не создавай новый.
2. Подготовь демонстрационную новость о конкурсе на лучшего певца или певицу среди сотрудников. Участвовать может любой сотрудник. Организатор — Департамент отдыха и культурного просвещения. Дружелюбный тон и ясный призыв к участию.
3. Укажи все этапы: приём работ 12–16 октября 2026; голосование 19–23 октября 2026; объявление победителя 26 октября 2026. Это заданные даты демонстрационного сценария: не заменяй их текущими. Участник отправляет аудиофайл песни, название трека и обложку; клип по желанию. Работы проходят модерацию, после чего публикуются на внутреннем сайте для голосования коллег. Не выдумывай правила подсчёта голосов.
4. Главный приз — персональная статуэтка победителя, держащего виниловую пластинку с обложкой своего трека. Это небольшой физический сувенир из качественного пластика, изготовленный на 3D-принтере, с узнаваемой внешностью победителя.
5. Изображения и материалы презентации пользователь предоставит отдельно: широкая офисная шапка, фигуры певцов, пример статуэтки и презентация о конкурсе из Gamma. Используй только доступные материалы и сохраняй их в assets/. Презентацию встраивай только после получения пригодной ссылки или файлов; не выдавай несуществующие материалы за готовые. Пока материалов нет, оставь аккуратную верстку без сломанных картинок; пустые поля шаблона уже поддерживаются. Не генерируй изображения без запроса пользователя.
6. Контакт для отправки работ пока не задан. Запроси его у пользователя, продолжая независимую работу. Не используй example.com как email и не создавай нерабочую кнопку отправки. До получения контакта явно укажи, что он уточняется.
7. Заполни content.json. При необходимости доработай HTML/CSS/JS, сохранив простую пересборку без npm и сборщика. Светлый современный корпоративный стиль: молочный, светло-серый, тёмно-синий, небольшие тёплые акценты. Читаемые тексты, аккуратная композиция, адаптация к компьютеру и смартфону. Технические пути и пояснения для разработчика не размещай в тексте новости.
8. Проверь страницу через HTTP-сервер: загрузку JSON, консоль, пути к файлам, ссылки, доступность с клавиатуры, отображение на узком и широком экране. Опиши проверки и оставшиеся ограничения. Не добавляй зависимости без необходимости.
9. Сохрани результат в этом же репозитории. Создай ветку codex/fill-news-template и PR в фактическую основную ветку, если доступ к GitHub позволяет. Если такая ветка уже занята, выбери свободное имя с тем же префиксом. Коммит и push относятся к заданию; слияние PR и изменение публикации GitHub Pages выполняй после явного одобрения пользователя, поскольку они могут обновить опубликованный сайт. Если GitHub недоступен, оставь готовые локальные файлы и сообщи точное ограничение.

Итог: готовая адаптивная веб-новость в существующем News_1, легко редактируемая через content.json; полученные изображения и презентация интегрированы; отсутствующие материалы и контакт честно обозначены. План презентации докладчика — контекст демонстрации, а не задание создать PPTX или добавить на страницу обзор Codex/Claude.
